# Offline cache and privacy decisions

For a user recovering from loss of connectivity, classify requests and responses before selecting offline behavior. Default authenticated HTML, API/JSON, session or tenant data, tokens, CSRF and all mutations to network-only; never claim an offline write succeeded or queue it silently. A data-free offline page and explicitly allowlisted public versioned assets are optional when the task justifies them. Reject redirects, personalized or otherwise private responses even when the requested URL is on the allowlist. Preserve server authentication and authorization. [MDN caching](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Caching), source checked 2026-10-28.

Test user A → logout → user B in the same browser context. Enumerate all origin CacheStorage caches, keys and bodies for synthetic private markers; an empty named public cache alone proves nothing. Offline must not show A's data to B; failed POST/PUT must be visible and must not replay on reconnect. Version and purge only caches owned by this app; do not delete unrelated origin caches. If a safe public fallback is unavailable, show an explicit recoverable network error. A private-cache negative control must trigger the same oracle and then be removed.
