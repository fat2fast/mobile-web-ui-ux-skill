# Push and permission decisions

For a user who needs timely information, compare push with existing in-app or email alternatives. Request notification permission only after a clear direct user action and value explanation; never silently enroll or re-enroll. Detect support, permission, service-worker registration, subscription and actual delivery separately. A granted permission does not prove a subscription or delivery. Handle denied, revoked, unsupported, unsubscribed and logout states without blocking the task. iOS/iPadOS Web Push has Home Screen and gesture prerequisites; check the actual target. [WebKit](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/), checked 2026-10-28.

Use data-minimal payloads by default. Resolve click targets to same-origin allowed routes and reject external redirects, but require fresh server-side authorization for the destination and tenant. A same-origin URL alone is not authorization. Test denial and revocation, logout and cross-tenant target rejection; mock results prove client handling only. OS prompt, subscription and delivery remain NOT RUN unless each is actually exercised. No production push service or credential is implied by this guidance.
