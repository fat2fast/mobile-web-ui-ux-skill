# Optional installation decisions

For a returning user who benefits from quick access, explain the benefit and offer an unobtrusive dismissible install action only if the app and environment support it. Capture `beforeinstallprompt` only when it fires and call its prompt from a deliberate user gesture; the event is not universal and absence is not failure. Suppress redundant offers in observed standalone mode, but do not equate that mode with proof of install. Preserve all tasks when declined. [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeinstallprompt_event), checked 2026-10-28.

Where relevant, offer iOS Safari Share → Add to Home Screen guidance without asserting that a particular browser or OS will install it. For unknown/in-app browsers offer a normal browser link or continue in place; do not add a banner to a non-PWA project. Never trigger an install prompt without a deliberate user action, automatically request permission, force installation or impose a fixed nagging schedule. Pass when the user can dismiss the offer and complete the task; fail when the banner hides the action, fires without a gesture or claims success without evidence. OS installation is NOT RUN unless actually observed.
