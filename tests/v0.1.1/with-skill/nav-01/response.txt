## Mobile UX summary
- Main user task(s): On a 390px mobile viewport, find an order using search/filters, inspect its status and metadata, execute a follow-up action (individually or in bulk), navigate to order details when necessary, and return smoothly to the order list without losing context.
- Observed problem(s):
  1. At `@media(max-width: 600px)`, `aside` takes a fixed 100px width out of 390px, leaving only ~258px usable content width for `<main>` (accounting for 16px horizontal padding).
  2. The orders table enforces `min-width: 1080px` (`overflow-x-auto`). Status is located in column 4 and the "Follow-up" action is located in column 10, requiring extensive horizontal panning where users lose the order ID/customer row header context.
  3. Filter controls wrap into multiple vertical lines above the table, pushing initial content off-screen.
  4. After acting on an order or navigating into details (`/orders/:id`), the return path requires scrolling back up to the top "Back to orders" text link, and action feedback (`role="status"`) renders below the wide table out of immediate mobile view.
- Context / assumption(s): Admin web dashboard built with React 19, Tailwind CSS, and Vite. Desktop viewport and all existing capabilities (search, status filter, sort, reset, CSV export, multi-select, bulk follow-up, row follow-up, detail view, URL routing) must remain fully intact.

## Decisions

### 1. Navigation Shell: Responsive Header Toggle with Drawer
| Field | Value |
| --- | --- |
| Evidence | `INFERRED` from `src/style.css` (lines 8-10) and `src/main.jsx` (lines 27-28). The persistent 100px sidebar consumes ~26% of screen width at 390px, leaving only ~258px width for order operations. |
| Mobile task | Access admin sections (`Orders`, `Reports`, `Settings`) without permanently sacrificing 26% of screen width during order triage on 390px screens. |
| Candidates | 1. Collapsible top app bar with off-canvas navigation drawer on mobile (`< md:`), preserving persistent 220px sidebar on desktop.<br>2. Persistent bottom navigation bar.<br>3. Status quo (fixed 100px sidebar). |
| Selected | Collapsible top app bar with drawer on mobile. Reclaims full 390px width (358px usable content width) for the primary order workflow. Navigation between global admin sections is occasional rather than continuous. |
| Rejected | Persistent bottom navigation bar. Dedicating 56px permanent bottom height for 3 secondary links steals vertical space and directly conflicts with mobile virtual keyboards and sticky bulk action affordances. |
| Preserved | Desktop layout (`aside` width 220px at `md:`), existing route URLs (`/orders`, `/reports`, `/settings`), keyboard focus management, and client routing logic (`go`, `popstate`). |
| Verify | Load at 390px viewport: verify sidebar is hidden by default and toggle reveals full menu. Switch to ≥768px: verify persistent 220px sidebar displays. (`NOT RUN` — design recommendation). |

## Verification
- PASS — Source inspection of `src/main.jsx` and `src/style.css` confirmed layout bottlenecks: fixed 100px aside width on `< 600px`, 1080px table min-width, and wrapped filter layout.
- FAIL — None observed in existing baseline implementation.
- NOT RUN — Live browser interaction checks on proposed mobile UX recommendations (environment not executed to keep fixture unmodified per evaluation rules). Recommended manual verification steps:
  1. **Navigation Drawer Check**: Emulate 390×844px in Chrome DevTools. Verify navigation drawer toggle is visible, menu opens/closes with accessible focus, and content area spans full 390px.
  2. **Order Card Scanning & Action Check**: At 390px, search for "ORD-1001". Confirm order card displays status badge prominently. Tap "Follow-up" and verify feedback message displays immediately.
  3. **Bulk Selection Check**: At 390px, select 2 orders. Verify sticky bottom bar displays "Follow-up selected (2)". Tap the button and verify selection clears and feedback is announced.
  4. **Detail & Return Flow Check**: Tap order ID to open `/orders/ORD-1002`. Verify sticky header displays "← Back to orders". Tap "Record follow-up", then tap Back. Confirm return to `/orders` without layout jumps.
  5. **Viewport Matrix Check**: Test layout across 320px (iPhone SE min), 375px (iPhone mini), 390px (standard phone), 430px (Pro Max), 768px (tablet), and 1024px+ (desktop). Confirm desktop retains 220px sidebar and 1080px table.

## Remaining risks / next steps
- **Query Parameter Synchronization**: Search and filter states currently live in React component memory. Adding URL search parameters (`/orders?q=minh&status=Shipped`) will ensure filters persist across hard reloads and deep link sharing.
- **Touch Target Padding**: Ensure all mobile interactive controls (checkboxes, drawer toggle, card buttons) enforce a minimum 44×44px hit area with `touch-action: manipulation`.
- **Screen Reader Announcements**: Ensure action feedback updates using `aria-live="polite"` so mobile screen reader users are notified when follow-ups are recorded without shifting focus unexpectedly.
