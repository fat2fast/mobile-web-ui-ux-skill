# Decision comparison protocol

Freeze this protocol before generating outputs. Source prompts: [input-only prompts](comparison-prompts.md); expected reasoning: [case files](decisions/) are reviewer-only and must not enter either generation context. This fills the P00-05 protocol gap for P02; it does not imply P00 is wholly complete.

## Tier A: development regression

Use this tier to check a known skill failure quickly. The existing `make both` projects, or only `with-skill` for a targeted repair, may share a fixture workspace across cases. Start a new agent conversation for each case. Give it only the frozen case prompt and the relevant fixture and skill files; do not show previous answers, sibling case outputs, reviewer cases, or the rubric. Move old outputs outside the working project when convenient, and record any file reads that could have exposed them. A shared workspace is a possible exposure path, not proof of shared conversation or contamination.

For each case, retain the prompt and its SHA-256, fixture and skill hashes from `manifest.json`, model/runtime if exposed, a conversation/session locator if exposed, files actually read, raw response, checks actually run, and any accessible transcript source. Mark unavailable values `unknown`. Inspect the transcript for the case-specific input and source reads. If the exporter is cumulative, the wrong source was selected, or identity remains unclear, label provenance `ambiguous` and do not claim an independent transcript. Review frozen answers separately from generation, using the case-specific business invariants below. Rerun a failed case and a nearby counterexample after a small rule repair. Tier A results are development regression evidence only.

## Tier B: controlled A/B comparison

Use this tier for comparative superiority claims. Record for **each pair**: (1) model identifier/version, (2) exact prompt text/version, (3) tool access, (4) token budget, (5) time budget, (6) baseline commit plus fixture file hash, (7) workspace snapshot/path, (8) runtime OS/environment and any ambient instructions. Also record temperature/seed if the runtime exposes them; otherwise say unavailable. Each condition uses the same model, budget, prompt and tools. The skill condition loads only runtime `SKILL.md` and needed `references/`; the no-skill condition receives no skill instructions through prompt, files, ambient AGENTS or previous-session memory.

Use independent conversations with no access to sibling cases, earlier answers, or reviewer materials. Separate clean per-case workspaces are one way to enforce that boundary, but are not mandatory when an equivalent access boundary is demonstrated. Conditions may run sequentially or in parallel when their filesystems and agent contexts are isolated; concurrent timestamps alone do not indicate contamination. Freeze the model/settings, tools, budgets and ambient instructions before generation and retain independent runtime evidence where available; an agent-written run-info is self-reported metadata, not a transcript. Save unedited raw responses outside future generator workspaces, under versioned `tests/` archives with prompt ID, condition, model and timestamp. A reviewer who did not generate either answer compares the outputs after both are frozen. If only one pair is available, report it as one trial without generalizing. Note nondeterminism and repeat independent runs before broader claims.

Generated projects include a recorder under `scripts/archive-comparison-case.py`. After the response and run-info are written, use it to copy an accessible runtime `transcript.jsonl` into the selected case and replace local home/workspace paths with `/home/user` aliases in the archived copy and case outputs. Record the case-relative archive location, never the real transcript path. Supported home-prefix redaction covers Linux /home/<user> and /root, WSL /mnt/<drive>/Users/<user>, and Windows drive:/Users/<user> or backslash equivalents, including JSON-escaped paths. This is path redaction, not general secret removal; review archives before sharing. The runtime source remains untouched. If the runtime does not expose a transcript, record `unavailable` and do not create one. An in-session copy may omit events written afterward; mark it as a snapshot rather than a complete transcript. The manifest records the recorder's hash. The recorder checks case identity and prompt hash only; archive success does not attest fixture, skill, instruction or recorder hashes against the frozen manifest. Review those hashes separately before claiming snapshot provenance. Path redaction is the only permitted change to a frozen response for archival privacy; disclose it when reviewing byte-level provenance.

The current [comparison-project generator](../scripts/create-comparison-project.py) places all cases in each condition workspace. This supports Tier A when the case agent does not read sibling outputs or reviewer materials. It does not alone establish the stronger Tier B access boundary. Earlier exploratory runs are archived under [`tests/v.0.1.0/`](../tests/v.0.1.0/) and [`tests/v0.1.1/`](../tests/v0.1.1/); preserve both unchanged. Version labels identify saved runs, not proof that either condition passed this protocol.

Clarification added 2026-10-14 after the first comparison runs: parallel execution in isolated projects is valid. This changes no prompt, answer, or reviewer rubric and does not resolve other missing controls.

## Reviewer rubric

Targeted regression checks: `DATA-03` must keep the fixture's follow-up action available for selected Pending, Shipped, and Delivered orders unless an explicit rule changes eligibility. `FORM-01` advice should be concise; a separate implementation request must preserve required Name/Message validation and allow a syntactically valid `user@gmai.com` with an optional domain suggestion. `DATA-02` must not claim numeric improvement or `Verified` without measurements. `A11Y-01` must measure target circles and neighboring hit areas before claiming a WCAG spacing exception or conformance. Record source-only assertions separately from executed browser checks.

For each answer, mark `PASS`/`FAIL`/`NOT RUN` with quote or artifact: (a) task fit, (b) explanation of a viable rejected alternative, (c) preservation of functions/data/routes/desktop/accessibility, (d) honest verification status. Multiple patterns can pass if task-based reasons and preservation hold. Do not score words such as “cards”, “bottom nav” or “sheet”. Distinguish decision quality from implemented UX. Record false choices and link any amended rule to original case and raw answer; rerun failed case and nearby counterexample before calling a rule repair verified.

Tier B comparison is `NOT RUN` unless both raw outputs, exact controls, access boundary and independent review exist for a pair. If a required condition is unavailable, record the missing condition and replay steps; never manufacture a PASS. Tier A may report an individual regression result without a new no-skill run.
